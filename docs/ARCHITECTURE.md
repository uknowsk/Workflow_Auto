# 구조 한눈에 보기

## 전체 그림

```
   사용자 (브라우저)
        │  "사번 E1001의 이번주 주간보고를 작성해줘"
        ▼
   frontend (Next.js)     대시보드 / 내 에이전트 / 레시피 / 예약 / 앱스토어 / 관리자
        │  HTTP
        ▼
   backend (FastAPI) ──────────┐
        │                      │ 오래 걸리는 일은 큐로
        │                      │ 시간이 되면 도는 일도 큐로(예약)
        │                      ▼
        │                  redis ──> worker (백그라운드 처리 + 예약 시계)
        │                               │
        │                               ▼
        │                        오케스트레이터
        │                          │        │
        │                          │        └──> Gauss (OpenAI 호환 LLM)
        │                          │              "어떤 앱을 어떤 순서로 부를까"
        │                          ▼
        │                    MCP 호출 (표준)
        │                          ├──> 어댑터 A ──> 개발자 앱 A (안 고침)
        │                          ├──> 어댑터 B ──> 개발자 앱 B (안 고침)
        │                          └──> 어댑터 C ──> 개발자 앱 C (안 고침)
        ▼
   postgres   앱 목록 / 개인 카드 / 실행 이력 / 호출 통계
```

## 폴더

| 폴더 | 무엇 |
|---|---|
| `backend/app/api/` | 화면이 부르는 API (앱스토어, 카드, 실행, 레시피, 예약, 대시보드, 통계) |
| `backend/app/orchestrator/` | 요청을 읽고 앱을 골라 순서대로 부르는 핵심 + 레시피 실행기 |
| `backend/app/scheduler/` | 예약 시각 계산과 큐 등록 |
| `backend/app/llm/` | LLM 어댑터. Gauss 등 OpenAI 호환이면 무엇이든 꽂힘 |
| `backend/app/mcp_client/` | 등록된 앱(MCP 서버)을 부르는 클라이언트 |
| `backend/app/worker/` | Redis 큐 + 백그라운드 처리 |
| `frontend/` | Next.js 화면 (대시보드 / 내 에이전트 / 레시피 / 예약 / 앱스토어 등) |
| `official_apps/` | 기본으로 올라가는 공식 앱 3개 (회의록 정리 / 할 일·수명업무 / 사내 메일) |
| `templates/` | 개발자가 복사해 쓰는 어댑터 견본 (웹앱용 / PC 설치형용) |
| `example_app/` | 기존 앱 + 그 옆에 붙인 어댑터 완성 예시 |
| `config/` | 집/회사 프로필, 사내 앱 목록 |
| `docs/` | 규약과 안내 문서 |

## 요청 하나가 처리되는 과정

1. 사용자가 자연어로 요청 → `POST /api/runs`
2. 백엔드가 요청을 DB에 저장하고 **Redis 큐에 넣은 뒤 바로 응답**
   (100명이 동시에 눌러도 화면이 멈추지 않는 이유)
3. worker 가 큐에서 꺼내 오케스트레이터 실행
4. 오케스트레이터가 **부를 수 있는 앱 목록**을 만듦
   - 공식 앱 전부 + 요청자 본인의 개인용 앱
   - 역할 태그가 겹치면 하나만 남김 (`pick_apps()`)
5. 그 목록을 "도구 목록"으로 LLM 에게 넘김
6. LLM 이 "이 앱의 이 기능을 이렇게 불러 줘" 라고 답하면 실제로 호출
7. 결과를 LLM 에게 돌려주고, 더 부를 게 없을 때까지 4~6 반복 (최대 `LLM_MAX_STEPS`회)
8. LLM 이 마지막에 만든 문장을 최종 결과물로 저장
9. 앱을 부를 때마다 성공/실패와 걸린 시간이 `app_call_logs` 에 기록됨
10. 화면은 2초마다 `GET /api/runs/{id}` 로 진행 상황과 결과를 받아 감

## 핵심 데이터

| 테이블 | 무엇 |
|---|---|
| `apps` | 등록된 앱. 주소, 등급(개인용/대기/공식), 역할 태그, 등록자 정보 |
| `app_tools` | 앱이 가진 기능 목록. 등록/새로고침 때 MCP 로 자동 수집 |
| `agent_cards` | 사용자별 "자주 쓰는 에이전트" 카드 |
| `runs` | 요청 1건과 처리 결과 |
| `app_call_logs` | 앱 호출 1건씩의 기록. "이달의 앱" 통계의 원재료 |
| `recipes` | 저장해 둔 앱 호출 흐름(워크플로우) |
| `schedules` | 시간이 되면 스스로 실행되는 예약 |

## 바꿔 끼울 수 있게 만든 곳

| 부분 | 파일 | 왜 |
|---|---|---|
| LLM | `backend/app/llm/client.py` | Gauss ↔ 다른 모델을 환경변수만으로 교체 |
| 사용자 인증 | `backend/app/deps.py` | 사내 SSO 를 붙일 지점 |
| 앱 목록 | `config/apps.seed.json` | 회사 전용 목록을 코드 밖에 둠 |
| 대시보드 칸 | `config/dashboard.widgets.json` | 사내 앱 이름이 달라도 코드를 안 고침 |
| 사내 표준시 | `.env` 의 `SCHEDULER_TZ_OFFSET_MINUTES` | "매일 09시"가 어느 나라 9시인지 |

## 예약이 도는 과정

1. 사용자가 예약을 만듦 → `POST /api/schedules`
2. 서버가 **다음 실행 시각을 계산**해 Redis 큐에 미리 걸어 둠
   (`queue.enqueue_at`. 이미 돌고 있는 worker 의 예약 기능이라 새 프로세스가 없음)
3. 시각이 되면 worker 가 `run_schedule()` 실행 → 실행 기록(`runs`)을 하나 만들고
   자연어 요청이든 레시피든 평소와 똑같이 처리
4. 반복 예약이면 **끝나면서 다음 차례를 다시 걸어 둠**
5. 서버가 다시 뜰 때는 살아 있는 예약을 전부 다시 계산해 걺
   (`rearm_all()`. 서버가 내려가 있던 동안 예약이 조용히 사라지지 않게)

되돌릴 수 없는 앱(메일 발송 등)이 든 예약은 **만들 때** 확인을 받습니다.
예약이 도는 순간에는 화면 앞에 사람이 없어 그때는 물어볼 수 없기 때문입니다.

## 레시피가 오케스트레이터와 다른 점

| | 오케스트레이터 (`engine.py`) | 레시피 (`recipe.py`) |
|---|---|---|
| 무엇을 할지 | LLM 이 매번 새로 정함 | 이미 정해져 있음 |
| 속도 | 느림 (LLM 을 여러 번 부름) | 빠름 (마무리에만 한 번, 지시문 없으면 아예 안 부름) |
| 결과 | 매번 조금씩 다를 수 있음 | 같은 입력이면 같은 결과 |
| 언제 | 처음 해 보는 일 | 한 번 잘 돌아간 일을 다시 |

그래서 "한 번 자연어로 시켜 보고, 잘 나오면 레시피로 굳히고, 거기에 예약을 건다"가
이 플랫폼에서 일이 자리 잡는 흐름입니다.

## 대시보드가 데이터를 얻는 방법

"오늘 마감 할 일"이나 "회신 안 온 메일"은 플랫폼이 직접 계산하지 않습니다.
그 데이터는 할 일 앱, 메일 앱이 들고 있기 때문입니다. 대신 규칙만 들고 있습니다.

> 역할 태그가 `todo` 인 앱을 찾아 `list_due_tasks` 를 불러라

그런 앱이 등록돼 있으면 불러서 채우고, 없으면 빈 칸에 안내 문구를 둡니다.
나중에 앱이 생기면 **코드를 고치지 않아도** 그날부터 채워집니다.
어떤 칸을 띄울지는 `config/dashboard.widgets.example.json` 를 복사해 바꾸면 됩니다.

자세한 내용은 [DEPLOY_COMPANY.md](DEPLOY_COMPANY.md) 참고.
