# 첫 업무 시나리오: 회의록 → 할 일 → 메일 → 리마인드

한 문장으로 요청하면 앱 세 개가 이어서 일하는, 실제로 돌아가는 첫 업무 흐름입니다.

```
 "이 회의록 정리해서 담당자들에게 할 일 메일 보내줘"
            ↓
   📝 회의록 정리 앱      요약 + 담당자·기한이 붙은 할 일 추출
            ↓
   ✅ 할 일 앱            할 일 등록 (누가, 언제까지)
            ↓
   📧 사내 메일 앱        담당자별로 확인 메일 발송 (회신 기한 포함)
            ↓
   ⏰ 기한이 지나면        회신 안 한 사람에게만 리마인드 메일
```

## 준비

```bash
cp config/profiles/home.env.example .env
docker compose up -d --build
```

이러면 플랫폼(백엔드·화면)과 공식 앱 세 개가 함께 뜨고, 앱스토어에 자동으로
등록됩니다. 앱스토어 화면(http://localhost:3000/store)에 세 앱이 보이면 준비 끝입니다.

집에서는 메일이 **가짜 메일함**으로 설정돼 있어 실제로 아무것도 나가지 않습니다.

## 방법 1. 화면에서 한 문장으로 (사내 Gauss 연결 후)

1. http://localhost:3000 에서 요청창에 회의록을 붙이고 이렇게 씁니다.

```
아래 회의록을 정리해서 담당자별로 할 일을 등록하고, 담당자들에게 확인 메일을 보내줘.
회신 기한은 2일 뒤로 해줘.

9/18 플랫폼개발팀 주간회의
참석: 김로아 <roa@samsung.com>, 이하늘 <sky@samsung.com>, 최바다 <sea@samsung.com>
- 이하늘: API 규격서 초안 작성해서 9월 25일까지 공유
- 최바다 책임: 품질지표 취합 결과 다음주 월요일까지 회신 요청
- 담당: 김로아 - 사내 보안검토 요청서 제출 (9/22)
```

2. 메일 앱이 끼어 있으므로 **바로 실행되지 않고 계획을 보여 주며 멈춥니다.**
   "어떤 앱을 어떤 순서로 쓸지"를 확인하고 `이대로 진행`을 누르면 그때 메일이 나갑니다.
   (메일처럼 되돌릴 수 없는 일은 항상 이렇게 확인을 받습니다)
3. 결과가 나오면 화면에서 확인합니다.
   - 할 일: http://localhost:3000/tasks
   - 보낸 메일과 회신 현황: http://localhost:3000/mail

> LLM(Gauss)을 아직 안 붙였다면 이 방법은 실패합니다. 아래 방법 2로 확인하세요.

## 방법 2. LLM 없이 점검 스크립트로 (집에서 검증용)

오케스트레이터(LLM)가 할 일을 정해진 순서로 대신 부르는 스크립트입니다.
세 앱이 제대로 이어지는지 확인할 때 씁니다.

```bash
pip install mcp
python scripts/demo_scenario.py
```

출력은 6단계로 나옵니다.

```
1단계  회의록 정리 앱에 회의 메모를 넘깁니다
   할 일 3건 (이하늘 / 최바다 / 김로아, 기한 포함)
2단계  뽑아낸 할 일을 할 일 앱에 등록합니다
3단계  담당자별로 할 일 확인 메일을 보냅니다
   연결: mock (가짜 메일함) / 3통 발송 / 회신 기한 2일 뒤
4단계  한 사람만 회신한 것으로 표시합니다
5단계  회신 현황을 확인합니다
   미회신: 최바다, 김로아
6단계  회신하지 않은 사람에게 리마인드 메일을 보냅니다
   2명에게 리마인드를 보냈습니다.
```

내 회의록으로 해 보려면 `python scripts/demo_scenario.py --notes 내회의록.txt`.

끝난 뒤 http://localhost:3000/mail 에 메일 5통(원본 3 + 리마인드 2)이 쌓여 있고,
http://localhost:3000/tasks 에 할 일 3건이 보이면 성공입니다.

## 회신 기한 리마인드를 자동으로

지금은 사람이 버튼을 누르거나 오케스트레이터가 불러야 리마인드가 나갑니다.
플랫폼에 스케줄러가 붙으면 **아래 한 줄을 매일 아침에 걸어 두면 끝입니다.**

```
사내 메일 앱의 send_reminders(thread_key="", only_overdue=true)
```

- `only_overdue=true` : 회신 기한이 지난 사람에게만 보냅니다
- `thread_key` 를 비우면 모든 건을, 특정 건만 하려면 `meeting:<회의록id>` 를 넣습니다
- 같은 사람에게 몇 번 리마인드가 갔는지는 메일함 화면에 표시됩니다

## 회사에서 실제로 메일을 보낼 때

바꾸는 것은 `.env` 한 줄과 어댑터 파일 하나뿐입니다.

```bash
MAIL_ADAPTER=smtp        # mock(가짜 메일함) -> smtp(사내 메일)
MAIL_SMTP_HOST=...       # 회사에서 확인한 값
```

그리고 `official_apps/mail/adapters/smtp_imap.py` 의 `send()` 와 `fetch_replies()`
두 함수를 채웁니다. 앱의 나머지(도구, 회신 추적, 리마인드, 화면)는 그대로 돕니다.
자세한 내용은 [official_apps/README.md](../official_apps/README.md).

## 자주 겪는 문제

| 증상 | 확인할 것 |
|---|---|
| 앱스토어에 세 앱이 안 보인다 | `.env` 의 `SEED_FILE`, 그리고 `docker compose ps` 로 `app-mail/app-meeting/app-tasks` 가 떴는지 |
| 할 일에 담당자·기한이 비어 있다 | LLM 없이 규칙으로 뽑은 경우입니다. 결과의 `extracted_by` 가 `rule` 이면 Gauss 를 붙이면 좋아집니다 |
| 메일이 하나도 안 나간다 | 회의록에 담당자 **메일 주소**가 있어야 합니다. 없으면 `no_email` 로 돌려줍니다 |
| 리마인드 대상이 없다고 나온다 | 회신 기한이 아직 남았거나 모두 회신한 상태입니다. `only_overdue=false` 로 부르면 미회신자 전원에게 갑니다 |
| 메일함·할 일 화면이 비어 있다 | 화면이 앱을 직접 부릅니다. `.env` 의 `NEXT_PUBLIC_MAIL_API`, `NEXT_PUBLIC_TASKS_API` 주소를 확인하세요 |
