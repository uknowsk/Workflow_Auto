# 부서 공통 앱 · 부서 공통 카드

같은 부서 사람들이 같은 앱과 같은 카드를 쓰게 만드는 장치입니다.
개인 카드와 개인용 앱은 예전 그대로 돌아갑니다. 부서 쪽이 **옆에 하나 더** 생긴 것입니다.

## 왜 부서 표를 따로 만들었나

계정에는 원래 소속을 적는 칸(`users.dept`)이 있지만 그건 **사람이 적는 글자**입니다.
"SW개발팀", "sw 개발팀", "SW개발 팀" 이 같은 부서인지 시스템은 알 수 없습니다.
부서 공통 앱은 "같은 부서인가"를 정확히 따져야 하므로 부서를 표로 만들고
**부서 코드**로 묶습니다.

| 표 | 하는 일 |
|---|---|
| `departments` | 부서 하나. `code`(예: SW1) + `name`(예: SW개발팀) |
| `dept_members` | 어떤 사번이 어느 부서에 묶여 있는지. **"같은 부서인가"의 유일한 기준** |

한 사람이 여러 부서에 들어갈 수 있습니다(겸직, TF).

## "부서 공통 계정"을 어떻게 풀었나

부서용 로그인 계정(아이디·비밀번호를 부서원이 나눠 쓰는 것)은 만들지 않았습니다.
그렇게 하면 감사 기록에 "누가 했는지"가 전부 부서 계정으로 남아 사내 보안 요건을
못 맞추고, 비밀번호가 돌아다니게 됩니다.

대신 **주인을 부서로 두었습니다**. 쓰는 느낌은 부서 공통 계정과 같습니다.

- 부서 공통 앱: `apps.visibility = department` + `apps.owner_dept_code = <부서코드>`
- 부서 공통 카드: `agent_cards.dept_code = <부서코드>`

이러면 올린 사람이 부서를 옮기거나 퇴사해도 앱과 카드는 부서에 남습니다.
동시에 누가 등록하고 고쳤는지는 감사 기록에 사람 이름으로 남습니다.

## 역할 두 가지

| 역할 | 할 수 있는 일 |
|---|---|
| 부서원 `member` | 부서 공통 앱·카드를 **본다 / 쓴다** |
| 담당자 `manager` | 거기에 더해 부서 공통 앱·카드를 **등록·수정·삭제한다** |

부서를 만들고 부서원을 넣는 것은 관리자, 그리고 그 부서의 담당자입니다.

## 누구에게 보이나

앱 하나가 보이는 조건은 딱 세 가지입니다.

1. 관리자가 승인한 공식 앱(`approved`)
2. 내가 올린 앱
3. **내가 묶인 부서의 부서 공통 앱**

남이 올린 개인용 앱과 남의 부서 앱은 목록에도, 상세에도, 오케스트레이터
후보에도 들어가지 않습니다. 이 조건은 두 군데에 같은 모양으로 있습니다.

- `backend/app/api/apps.py` 의 `_visible_filter()` — 화면 목록
- `backend/app/orchestrator/engine.py` 의 `load_bindings()` — 실행 후보

**한쪽만 고치면 목록에는 안 보이는데 실행은 되는 구멍이 생깁니다. 늘 같이 고치세요.**
`backend/tests/test_departments.py` 가 이 두 가지를 같이 확인합니다.

## 역할 태그가 겹칠 때 누가 이기나

같은 `capability_tag` 를 가진 앱이 여러 개면 하나만 씁니다. 순서는

1. 요청문에 이름을 직접 적은 앱
2. 내 카드에 넣어 둔 앱
3. 내가 올린 개인용 앱
4. **내 부서의 부서 공통 앱**
5. 전사 공식 앱

부서 앱이 공식 앱보다 앞인 이유: 부서가 일부러 자기 부서용으로 올린 앱은
그 부서 사정에 맞춰져 있으니 전사 공통 앱보다 그 부서원에게 더 맞습니다.

## 쓰는 순서

1. 관리자 화면 → **부서** 탭 → 부서 코드와 이름을 넣고 «부서 추가»
2. 같은 화면에서 «부서원 관리» → 사번을 넣고 역할을 고릅니다(담당자 1명 이상)
3. 담당자가 앱스토어에서 «＋ 앱 등록» → "누가 쓰는 앱인가요?"에서 부서를 고릅니다
   - 이미 올려 둔 개인용 앱은 목록의 «○○팀 공통으로 내기» 버튼으로 바꿀 수 있습니다
4. 담당자가 «내 에이전트» 화면에서 «+ ○○팀 공통 카드» 로 카드를 만듭니다
5. 부서원은 로그인만 하면 «부서 공통 카드» 칸과 앱스토어에서 바로 보입니다

## 사내 SSO 를 붙일 때

SSO 가 부서 정보를 내려주면 `departments.code` 를 사내 부서코드와 맞추고,
`app/auth/backend.py` 의 SsoBackend 에서 `departments.join(db, code, user_id)` 를
부르면 끝입니다.

그전까지는 다리를 하나 놔 뒀습니다. 계정에 적힌 소속 글자가 부서의 코드나 이름과
**정확히 같으면** 로그인할 때 자동으로 그 부서에 묶입니다
(`app/departments.py` 의 `sync_from_profile`). 비슷해 보인다고 묶지는 않습니다 —
잘못 묶이면 남의 부서 앱이 보이기 때문입니다. 이미 부서가 있는 사람은 건드리지
않습니다(관리자가 명단에서 옮긴 것을 로그인할 때마다 되돌리면 안 되니까요).
