# Workflow Auto

자연어로 요청하면, 오케스트레이터가 **등록된 앱들을 알아서 골라 순서대로 부르고**
결과를 합쳐 최종 산출물을 만들어 주는 사내 업무 자동화 앱입니다.

```
"사번 E1001의 이번주 주간보고를 작성해줘"
        ↓
  오케스트레이터가 계획을 세우고
        ↓
  인사조회 앱 호출 → 보고서양식 앱 호출
        ↓
  완성된 주간보고 문서
```

개발자들이 각자 만든 앱은 **고치지 않고** 옆에 얇은 어댑터만 붙여 등록합니다.
등록된 앱은 앱스토어처럼 모아 두고, 사용자는 자주 쓰는 것을 카드로 저장해 씁니다.

한 번 잘 돌아간 흐름은 **레시피**로 저장해 버튼 하나로 재실행하고,
**예약**을 걸어 두면 시간이 됐을 때 스스로 돕니다.

> 지금은 **실행되는 최소 뼈대**입니다. 화려한 UI나 완성 기능은 아직 없습니다.

## 5분 만에 띄우기

필요한 것: Docker Desktop (또는 Docker + Compose)

```bash
git clone https://github.com/uknowsk/workflow_auto.git
cd workflow_auto

# 1) 설정 파일 만들기 (집에서 개발할 때)
cp config/profiles/home.env.example .env

# 2) 전부 띄우기
docker compose up -d --build
```

| 주소 | 무엇 |
|---|---|
| http://localhost:3000 | 화면 (내 에이전트) |
| http://localhost:3000/dashboard | 첫 화면 — 할 일·메일·예약을 한 눈에 |
| http://localhost:3000/tasks | 할 일 / 수명업무 |
| http://localhost:3000/mail | 메일함 (보낸 메일·회신 현황) |
| http://localhost:3000/recipes | 워크플로우 레시피 |
| http://localhost:3000/schedules | 예약 |
| http://localhost:3000/store | 앱스토어 (공식 앱 10개가 등록돼 있습니다) |
| http://localhost:8000/docs | API 문서 (직접 눌러 볼 수 있습니다) |
| http://localhost:8000/health | 잘 떴는지 확인 |

예시 앱이 자동으로 등록되어 있으므로, 화면에서 바로 요청을 넣어 볼 수 있습니다.

> LLM 을 아직 안 붙였다면 앱 등록·카드·앱스토어까지는 다 되고,
> 실제 요청 실행만 실패합니다. 아래에서 LLM 을 연결하세요.

## Gauss(사내 LLM) 연결하기

`.env` 파일에서 아래 세 줄만 바꾸면 됩니다. 코드는 건드리지 않습니다.

```bash
LLM_BASE_URL=https://사내-gauss-주소/v1    # 보통 /v1 로 끝납니다
LLM_API_KEY=발급받은_키
LLM_MODEL=사내에서_알려준_모델명
```

그리고 Gauss 가 **tool calling(함수 호출)** 을 지원하는지에 따라 한 줄 더:

```bash
LLM_TOOL_MODE=native   # 함수 호출 지원 → 이게 제일 깔끔합니다
LLM_TOOL_MODE=json     # 지원 안 함 → 프롬프트로 JSON 을 받아내는 우회 방식
```

바꾼 뒤 `docker compose up -d` 를 다시 실행하면 적용됩니다.
Gauss 가 OpenAI 호환 형식이라 이것만으로 끝납니다.

## 로그인

지금은 사번 + 비밀번호입니다. 사내 SSO 는 나중에 붙일 수 있게 자리를 비워 뒀습니다
(`backend/app/auth/backend.py` 의 `SsoBackend`). 그 파일 하나만 채우고
`.env` 의 `AUTH_BACKEND=sso` 로 바꾸면 나머지 코드는 손댈 필요가 없습니다.

### 관리자 계정

관리자 계정은 `.env` 의 `ADMIN_ID` / `ADMIN_PASSWORD` 로 정해지고, 서버가 처음 뜰 때
그 값으로 만들어집니다. 코드나 저장소 파일에는 비밀번호가 들어가지 않습니다.

```bash
ADMIN_ID=admin
ADMIN_PASSWORD=여기에_비밀번호      # 이 줄은 .env 에만, 저장소에는 올리지 마세요
```

계정이 이미 있으면 비밀번호는 건드리지 않습니다(화면에서 바꿔 뒀을 수 있으니까요).
비밀번호를 잊었을 때만 `ADMIN_RESET_PASSWORD=true` 로 한 번 띄운 뒤 다시 `false` 로 돌리세요.

사내 SSO 를 붙인 뒤에는 `ADMIN_SSO_IDS` 에 적은 아이디(쉼표 구분, 예: `sk1980.kim`)로
로그인하면 자동으로 관리자가 됩니다.

## 내 앱 붙이기

**내 앱은 고치지 않습니다.** 옆에 통역사 역할을 하는 작은 파일 하나를 만들어
같이 켜 두면 됩니다.

개발을 몰라도 됩니다 → **[docs/WRAPPER_PROMPT.md](docs/WRAPPER_PROMPT.md)** 의
글상자를 복사해서 Claude / Codex / Cline 에 붙여넣으면 알아서 만들어 줍니다.

등록하는 방법은 세 가지입니다.

| 방법 | 언제 |
|---|---|
| 주소만 등록 | 어댑터를 내가 켜 두고 주소만 알려줄 때 |
| GitHub 주소 | 코드가 사내 Git 에 있을 때 |
| ZIP 업로드 | 코드를 압축해서 올릴 때 |

GitHub·ZIP 으로 올릴 때는 패키지 안에 `workflow_app.json` 을 넣어 주세요.
앱 이름·설명·역할 태그가 자동으로 채워집니다.

- 견본: `templates/mcp_adapter_http/` (웹앱용), `templates/mcp_adapter_cli/` (PC 설치형용)
- 완성 예시: `example_app/` — 기존 앱을 한 줄도 안 고치고 붙인 사례
- 규약 원문: [docs/WRAPPER_SPEC.md](docs/WRAPPER_SPEC.md)

## 서버에서 도는 앱, 내 PC에서 도는 앱

서버는 남의 PC에 깔린 프로그램을 직접 실행할 수 없습니다. 그래서 앱마다
"어디서 도는지"를 정합니다.

- **서버 구동** — 웹앱·API 형태. 서버가 직접 띄웁니다. 남들도 쓸 수 있습니다.
- **개인 PC 구동** — 설치형 프로그램. 내 PC에 **Launcher**(작은 연결 프로그램)를
  깔면, Launcher 가 서버에 "일 있나요?" 하고 물어보러 와서 대신 실행합니다.
  PC 에서 밖으로 나가는 연결만 쓰므로 방화벽을 열 필요가 없습니다.

> 지금 뼈대에는 Launcher 가 쓸 API 만 들어 있습니다. Launcher 프로그램 자체는
> 다음 단계입니다.

## 되돌릴 수 없는 작업은 먼저 확인합니다

메일 발송이나 결재 상신처럼 되돌릴 수 없는 앱은 등록할 때 "확인 필요"로
표시합니다. 그런 앱이 계획에 끼면 오케스트레이터가 바로 실행하지 않고,
**"이 순서로 이 앱들을 쓸게요"** 하고 계획을 보여 준 뒤 승인을 기다립니다.

## 양식 저장소

결과물을 채워 넣을 틀(주간보고 양식, 출장보고서 등)을 중앙 서버에 보관합니다.
요청할 때 양식을 고르면 오케스트레이터가 그 틀에 맞춰 결과를 씁니다.
마크다운·텍스트 양식은 자동 적용되고, 엑셀·워드는 지금은 보관과 내려받기까지입니다.

## 죽은 앱 자동 감지

비개발자가 만든 앱은 어느 날 조용히 꺼집니다. 서버가 5분마다 "살아있니?"를
확인해서 앱스토어에 표시하고, 연속으로 실패하면 등록자에게 알림을 남깁니다.
등록자 연락처를 받아 두는 이유가 여기 있습니다.

## 감사 기록

누가, 언제, 어떤 요청으로, 어떤 앱을 어떤 내용으로 불렀는지 남깁니다
(관리자 화면 › 감사 기록). 사내 보안 요건에 대비한 것입니다.
요청문과 결과는 원문 전체가 아니라 앞부분 요약만 남깁니다.

## 첫 업무 시나리오

공식 앱 세 개(회의록 정리 · 할 일/수명업무 · 사내 메일)가 기본으로 등록됩니다.
한 문장으로 요청하면 이렇게 이어집니다.

```
"이 회의록 정리해서 담당자들에게 할 일 메일 보내줘"
   → 회의록 요약 + 할 일 추출 → 할 일 등록 → 담당자별 확인 메일
   → 회신 기한이 지나면 회신 안 한 사람에게만 리마인드
```

집에서는 메일이 **가짜 메일함**으로 설정되어 실제로 나가지 않습니다. LLM 없이
흐름만 확인하려면 `python scripts/demo_scenario.py` 를 돌려 보세요.
자세한 방법은 **[docs/FIRST_SCENARIO.md](docs/FIRST_SCENARIO.md)**,
앱별 기능은 **[official_apps/README.md](official_apps/README.md)** 에 있습니다.

## 앱 등급과 승인

| 등급 | 누가 쓰나 |
|---|---|
| 개인용 | 올린 사람만. 등록하면 처음엔 전부 여기서 시작합니다 |
| 부서 공통 | 그 부서에 묶인 사람 전원 |
| 승인 대기 | 올린 사람만. 관리자 검토 중 |
| 공식 | 모두 |

오케스트레이터가 부를 수 있는 앱은 **공식 앱 전부 + 요청한 본인의 개인용 앱
+ 본인이 묶인 부서의 부서 공통 앱**입니다.
남이 올린 개인용 앱과 남의 부서 앱은 절대 불리지 않습니다.

비슷한 역할의 앱이 여러 개면 (예: 사내규정 검색 앱 A 와 B) `capability_tag` 가
같은 것끼리 하나만 골라 씁니다. 본인이 카드에 넣어 둔 앱이 부서 앱보다,
부서 앱이 공식 앱보다 우선합니다.

관리자는 `.env` 의 `ADMIN_USER_IDS` 에 사번을 적어 지정합니다.

## 부서 공통 앱과 부서 공통 카드

부서마다 자주 쓰는 앱이 다릅니다. 부서를 만들어 부서원을 묶어 두면, 그 부서의
앱과 카드가 **부서원 모두의 화면에 같이** 보입니다. 개인 카드는 그대로입니다.

```
관리자: [부서] 탭에서 부서 만들기 → 부서원 넣기(담당자 1명 이상)
담당자: 앱스토어에서 앱을 "○○팀 공통"으로 등록
        내 에이전트에서 "+ ○○팀 공통 카드"
부서원: 로그인만 하면 부서 공통 카드와 앱이 이미 있습니다
```

부서용 공용 로그인 계정은 만들지 않습니다(누가 했는지 감사 기록에 남아야 하니까요).
대신 앱과 카드의 **주인이 부서**라서, 올린 사람이 부서를 옮기거나 퇴사해도 남습니다.
자세한 규칙은 **[docs/DEPARTMENTS.md](docs/DEPARTMENTS.md)** 에 있습니다.

## 워크플로우 레시피 — 한 번 시키고, 다음부터는 버튼 하나

요청을 자연어로 한 번 시켜 보고 결과가 잘 나왔으면, 결과 아래의
**"이 흐름을 레시피로 저장"** 을 누르세요. 그때 불린 앱들의 순서가 그대로 저장됩니다.

```
"회의록 정리해서 할 일 뽑고 담당자에게 메일 보내줘"   ← 처음엔 이렇게 시키고
        ↓  잘 나왔다
   [이 흐름을 레시피로 저장]
        ↓
/recipes 에서 버튼 하나로 재실행  ← 다음부터는 이렇게
```

카드가 앱 하나라면, 레시피는 **앱 여러 개를 엮은 카드**입니다.
매번 달라지는 값은 `{{회의록}}` 처럼 빈칸으로 두면 실행할 때 물어봅니다.
앞 단계의 결과를 다음 단계로 넘길 때는 `{{step1}}` 을 씁니다.

레시피는 LLM 에게 계획을 다시 묻지 않아 **빠르고, 같은 입력이면 같은 결과**가 나옵니다.

## 예약 — 시간이 되면 알아서

`/schedules` 화면에서 등록합니다.

| 이럴 때 | 이렇게 |
|---|---|
| 회신기한 하루 전에 리마인드 | "특정 시각에 한 번" + 기한 입력 + **하루 전에** |
| 매주 월요일 아침 주간보고 초안 | "매일 정해진 시각" + 09:00 + 요일 **월** |
| 수명업무 기한 체크 | "일정 간격마다" |

무엇을 할지는 **자연어 요청** 또는 **저장해 둔 레시피** 중에 고릅니다.

> 메일 발송처럼 되돌릴 수 없는 작업이 끼어 있으면, 예약을 **만들 때** 한 번
> 확인 체크를 받습니다. 예약이 실제로 도는 순간에는 화면 앞에 사람이 없어
> 그때는 물어볼 수가 없기 때문입니다.

"매일 09시"의 9시는 `.env` 의 `SCHEDULER_TZ_OFFSET_MINUTES` 가 정합니다 (한국은 540).

## 첫 화면 (대시보드)

로그인하면 `/dashboard` 에 오늘 챙길 것이 모여 있습니다.

- 오늘 마감 할 일, 회신 안 온 메일, 수명업무, 다가오는 산출물
- 예약된 작업, 내 레시피, 최근 실행 결과, 이달의 앱

위쪽 네 칸은 플랫폼이 계산하지 않고 **앱에게 물어봅니다**. 예를 들어 역할 태그가
`todo` 인 앱을 찾아 `list_due_tasks` 를 부릅니다. 그런 앱이 아직 없으면 빈 칸으로
두고, 나중에 등록되면 **코드를 고치지 않아도** 그날부터 채워집니다.

어떤 칸을 띄울지는 `config/dashboard.widgets.example.json` 를 복사해 바꾸고
`.env` 의 `DASHBOARD_WIDGETS_FILE` 로 가리키면 됩니다.

## 도구 서랍 — 어느 화면에서든 왼쪽 구석에

화면 왼쪽 구석에 도구 인덱스가 세로로 붙어 있습니다. 아이콘을 누르면 오른쪽으로
패널이 펼쳐지고, 그 안에서 바로 쓰면 됩니다. 보던 화면을 떠나지 않아도 되고,
`넓게` · `전체 화면` 으로 넓힐 수 있습니다. `/tools` 화면에 가면 같은 도구를
처음부터 넓게 펼쳐 놓고 쓸 수 있습니다.

들어 있는 도구 8가지:

| 도구 | 하는 일 |
| --- | --- |
| 그리기 | 펜·지우개·직선·사각형·원·화살표·글자. 되돌리기, PNG 내려받기, 계정에 저장·불러오기 |
| 계산기 | 괄호와 거듭제곱까지. 적는 동안 결과를 미리 보여 주고, 계산한 식이 쌓입니다 |
| 단위 변환 | 길이·무게·넓이·부피·시간·데이터·온도. 평, 근, 돈, 자도 됩니다 |
| 세계 시계 | 해외 지사 시각과 근무 시간 여부. 서울 기준 시각을 넣으면 각 도시가 몇 시인지 |
| 날짜 계산 | D-day, 두 날짜 사이 일수, 영업일 더하기 |
| 타이머 | 타이머와 스톱워치. 시간이 되면 소리로 알려 줍니다 |
| 메모 | 계정에 저장되는 메모. 적다가 멈추면 알아서 저장됩니다 |
| 텍스트 정리 | 글자 수·바이트 수 세기, 공백·줄바꿈 정리, JSON 펴기 |

메모와 그림만 서버에 저장됩니다(`/api/tools/notes`, `/api/tools/drawings`).
나머지는 브라우저 안에서 끝나므로 서버도 인터넷도 필요 없습니다. 바깥에서
받아오는 라이브러리나 글꼴도 쓰지 않아 폐쇄망에서 그대로 돕니다.

한 번 연 도구는 닫아도 그대로 살아 있습니다. 타이머를 켜 둔 채 계산기를 봐도
타이머는 계속 돌고, 그리다 만 그림도 남아 있습니다. 마지막으로 연 도구는
다음에 들어올 때 다시 열립니다.

## 이달의 앱

앱이 불릴 때마다 성공/실패가 기록됩니다. `/stats` 화면에서 월별 순위를 볼 수 있습니다.
순위는 **성공한 호출 수** 기준이라, 많이 불렸어도 계속 실패한 앱은 올라오지 않습니다.
등록자 이름과 연락처도 같이 나오므로 시상과 유지보수 문의에 씁니다.

## 회사에서 이어 개발하기

집에서 만든 것을 회사로 가져가 이어가는 방법, 그리고 폐쇄망 확인 사항은
**[docs/DEPLOY_COMPANY.md](docs/DEPLOY_COMPANY.md)** 에 정리해 두었습니다.

핵심은 하나입니다. **회사에서만 아는 값은 전부 `.env` 와 `config/` 에 있고,
코드는 집과 회사가 같습니다.**

## 화면 디자인 — 미니멀 화이트

화면의 색·글꼴·여백·모서리는 전부 `frontend/app/globals.css` 의 CSS 변수
한 곳에 모여 있습니다. 화면 파일에는 색상 코드나 px 를 직접 쓰지 않습니다.
나중에 다크 모드를 넣더라도 이 변수 값만 갈아 끼우면 됩니다.

바깥 인터넷에서 받아오는 글꼴·아이콘·CDN 이 하나도 없습니다.
기기에 이미 있는 글꼴만 쓰므로 폐쇄망에서도 화면이 깨지지 않습니다.

새 화면을 만들 때 쓰는 공통 부품(버튼, 카드, 배지 등)의 사용법은
[docs/DESIGN.md](docs/DESIGN.md) 에 정리돼 있습니다.

## 폴더

| 폴더 | 무엇 |
|---|---|
| `backend/` | FastAPI. API + 오케스트레이터 + 큐 |
| `frontend/` | Next.js 화면 (대시보드 / 내 에이전트 / 레시피 / 예약 / 앱스토어 등) |
| `official_apps/` | 기본으로 올라가는 공식 앱 10개 |
| `templates/` | 개발자가 복사해 쓰는 어댑터 견본 |
| `example_app/` | 기존 앱 + 어댑터 완성 예시 |
| `config/` | 집/회사 프로필, 사내 앱 목록 |
| `docs/` | 규약과 안내 문서 (Wrapper 규약, 구조, 화면 디자인) |

주요 API는 http://localhost:8000/docs 에서 직접 눌러 볼 수 있습니다.

구조가 궁금하면 [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) 를 보세요.

## 자주 겪는 문제

| 증상 | 확인할 것 |
|---|---|
| `docker compose up` 이 느리다 | 처음 한 번은 이미지를 받느라 몇 분 걸립니다 |
| 화면은 뜨는데 앱 목록이 비어 있다 | `.env` 의 `SEED_FILE` 값과 `/health` 를 확인하세요 |
| 요청 실행이 계속 실패한다 | `.env` 의 `LLM_*` 값. `/health` 에 현재 설정이 보입니다 |
| 등록한 앱이 `unreachable` 이다 | 어댑터가 켜져 있는지, 주소가 `/mcp` 로 끝나는지 |
| 폐쇄망이라 설치가 안 된다 | `.env` 에 `PIP_INDEX_URL`, `NPM_REGISTRY` 를 넣으세요 |
| 로그인이 안 된다 | `.env` 의 `ADMIN_ID` / `ADMIN_PASSWORD` 확인 |
| 요청이 "확인 필요"에서 멈춰 있다 | 정상입니다. 계획을 보고 "이대로 진행"을 누르세요 |
| 예약을 저장하려는데 막힌다 | 되돌릴 수 없는 앱이 낀 예약입니다. 자동 실행 체크를 켜세요 |
| 예약 시각이 한 시간씩 어긋난다 | `.env` 의 `SCHEDULER_TZ_OFFSET_MINUTES` (한국은 540) |
| 예약이 안 돈다 | `worker` 컨테이너가 떠 있는지, `SCHEDULER_ENABLED=true` 인지 |
| 대시보드 칸이 전부 비어 있다 | 정상입니다. 해당 역할 태그의 앱을 등록하면 채워집니다 |
